Step 1: Installation

Install AeroLoom directly from this official GPG-signed APT repository on Debian or Ubuntu:

# 1. Setup keyring directory and fetch GPG key
sudo install -m 0755 -d /etc/apt/keyrings
sudo apt-get update && sudo apt-get install -y --no-install-recommends curl gnupg

curl -fsSL "https://albygt.github.io/aeroloom-apt/keys/aeroloom-archive-keyring.asc" \
  | gpg --dearmor \
  | sudo tee /etc/apt/keyrings/aeroloom-archive-keyring.gpg > /dev/null

sudo chmod 0644 /etc/apt/keyrings/aeroloom-archive-keyring.gpg

# 2. Add AeroLoom APT repository
echo "deb [signed-by=/etc/apt/keyrings/aeroloom-archive-keyring.gpg] https://albygt.github.io/aeroloom-apt/ stable main" \
  | sudo tee /etc/apt/sources.list.d/aeroloom.list

# 3. Synchronize package lists and install AeroLoom
sudo apt-get update
sudo apt-get install -y --no-install-recommends aeroloom

# 4. Launch the interactive onboarding wizard
sudo aeroloom init

Trustworthiness & Production-Grade Engineering

Why engineers trust AeroLoom on mission-critical Debian & Ubuntu production servers:

🔐 GPG Cryptographic Signing

Every .deb archive and release manifest is signed with GPG keys. Your OS validates authenticity before installation.

🔍 100% Auditable Shell

Strict POSIX shell code. No black-box compiled binaries, zero closed-source blobs, zero telemetry, and zero tracking.

⚖ Cryptographic Modulus Checks

Verifies RSA moduli between public certificates and private keys before Nginx reloads to prevent broken TLS handshakes.

🛡 Zero-Downtime Safe Fallbacks

If ACME fails or DNS propagates slowly, fallback self-signed certificates remain active. Nginx never drops traffic.

🔏 Sandboxed Systemd Units

Renewal jobs execute under isolated systemd oneshot units with PrivateTmp=true, ProtectSystem=full, and ProtectHome=true.

⚡ Automated Chaos Test Suite

Validated against comprehensive automated test suites including simulated network partitions, NTP drift, and race conditions.

Alternative: Declarative Table (apps.conf)

For GitOps and power users, manage all virtual hosts in /etc/aeroloom/apps.conf:

# /etc/aeroloom/apps.conf
# <domain>             <action>  <target>
api.example.com        proxy     127.0.0.1:3000
app.example.com        proxy     127.0.0.1:8080
static.example.com     root      /var/www/static

Apply changes with a single command: sudo aeroloom sync

CLI Reference

Command Description
sudo aeroloom init Interactive onboarding wizard with DNS pre-check and port auto-discovery
sudo aeroloom sync Idempotent sync: compiles vhosts, reloads Nginx, and issues/renews certificates
sudo aeroloom renew Silent background renewal audit (used by systemd timer)
sudo aeroloom renew -v Verbose renewal audit showing remaining validity for each domain
sudo aeroloom compile Compiles vhosts and bootstraps self-signed certs (no ACME network calls)
sudo aeroloom check <domain> Checks whether a domain certificate requires issuance or renewal

Production Hardening & Safeguards

  • Race-Free Concurrency: Atomic process mutex directory locks (/run/aeroloom.lock) prevent overlapping cron jobs.
  • Atomic Staging: Certificates are generated in .staging and validated before being atomically moved into place.
  • Post-Reload Probing: Probes live port 443 with openssl s_client to verify Nginx activated the new certificate.
  • Rate-Limit Protection: Validates DNS resolution before querying Let's Encrypt to prevent IP rate-limiting.

Uninstall & Decommissioning

# Standard uninstall (preserves configs & SSL certificates):
sudo ./uninstall.sh

# Complete purge (removes all certificates, ACME data, and configs):
sudo ./uninstall.sh --purge
